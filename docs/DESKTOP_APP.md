# AI Bro 桌面 App

AI Bro 当前交付 **Mac 原生 App**：SwiftUI / AppKit 管理窗口、导航和原生日程，WKWebView 承载对话与文档工作区。本机 Python 服务处理工作区存储、文件解析、模型连接与同步。旧 Electron 入口仍留在仓库供开发使用，浏览器预览也只用于辅助检查；它们不是当前的独立产品交付目标。

本文描述当前源码。公开安装包可能尚未包含正在验收的改进，请以具体 [Release](https://github.com/zihenghe04/AIBro/releases) 为准。安装、签名、系统要求和发行构建见[安装与构建](DISTRIBUTION.md)。

## 运行与数据目录

正式 App 从自身 `Contents/Resources` 加载应用资源与内置 Python，启动只监听回环地址的服务，并使用动态端口。网页内容、原生桥接及原生样式共同构成一个桌面工作区，不要求用户另开浏览器。

| 运行方式 | 数据目录 |
| --- | --- |
| 正式安装的 AI Bro.app | `~/Library/Application Support/ai-workstation` |
| 从源码运行的原生预览 | 仓库相邻的 `.aibro-native-preview.noindex/workspace` |
| 显式原生 QA | 新建临时隔离目录，不应载入正式资料 |

正式原生 App 使用 `native-session.lock` 阻止第二个实例同时接管同一工作区。应用更新替换程序和运行资源，不主动删除用户目录；不要把删除数据目录作为常规更新步骤。

工作区中主要内容包括：

- `workspace.sqlite3`：规范工作区数据、版本与同步队列；`workspace.json` 是兼容镜像，手改镜像不能代替数据库更新。
- `files/`：受管附件原件及解析关联数据。本机授权目录中的文件可能仍在工作区外，需要单独备份。
- `agenda.json`：原生日程存储，通过 App 的本机适配与工作区同步。
- `native-preferences.json`：当前设备的原生连接偏好等设置。
- 独立的凭据和会话目录：不会作为普通知识资料同步或导出，详见下一节。

正常退出后备份整个数据目录，或使用一致性 SQLite 备份并同时保留附件；不要只复制运行中的数据库而漏掉 WAL。同步会传播删除与修改，不能替代历史备份。完整目录可能含登录凭据，不可直接上传到公开 Issue。详见[自托管同步](CLOUD_SYNC.md)。

## 模型凭据与登录

### 自定义 API 与 Embedding Key

当前原生实现默认使用**本机加密文件**，不依赖钥匙串弹窗：

```text
<数据目录>/native-credentials/v2/
  device-key.bin
  api.sealed
  embedding.sealed
```

API 与 Embedding 凭据分别使用 AES-GCM 加密，目录权限为 `0700`，文件权限为 `0600`。密钥与密文位于同一 macOS 用户目录，因此不能防止拥有该目录读取权限的进程或完整备份持有者解密；不能将其描述为与系统钥匙串同等隔离。

正常读取、测试连接和保存不请求钥匙串密码。旧钥匙串或 Electron 凭据只尝试静默迁移；无法读取时要求重新粘贴 Key 保存，不修改钥匙串密码、ACL 或原记录。损坏、权限异常和密钥缺失会报错，不悄悄改写为新空存储。

保存时留空 Key 表示保留同一服务来源的已存凭据；更换服务来源不能沿用旧 Key。保存失败、未保存输入、本机凭据可读取和真实模型请求成功是不同状态。连接测试能读取模型列表，也不等于该服务已经验证全部工具或附件能力。实现与错误处理见 [NativeCredentials.swift](../native/Sources/AIBro/NativeCredentials.swift)。

### Codex 账号通道

该通道通过本机官方 Codex CLI 的 `app-server` 接口完成认证与调用；它不是复用其他 App 的登录文件。AI Bro 使用自己的认证目录，由运行时管理登录与刷新，凭据不作为工作区资料导出或同步。

需要单独安装可用的官方 CLI；本地集成会检查常见安装路径，也可通过 `AI_WORKSTATION_CODEX_BIN` 指定。具体账号可用模型与能力由实际服务决定。自定义 API 与账号通道分别配置；API 与 embedding 额度不能从账号登录状态推断。

### 同步会话

同步服务会话由本机 Python 后端保存到 `cloud-sync/cloud-session.json`，当前为权限受限的本地文件（目录 `0700`、文件 `0600`），**不是上述 AES-GCM 模型凭据文件**。权限限制不等于加密。启动、连接和断开不再读取钥匙串；旧钥匙串会话需要通过 SSH 重新授权或重新登录，原条目保留。

API Key、同步会话、本机目录路径及权限不随工作区同步。手动整目录备份仍可能包含它们，分享或迁移备份时需单独处理会话与凭据。

## 项目、对话与附件

项目组织对话、资料、成果和任务；文件夹用于整理对话，不自动改变项目归属。原始资料与分析产物通过来源关联，文件保存、文字索引、AI 分析和人工审阅是不同阶段。

- 文件可以加入对话或项目；项目中单纯保存资料不等于自动发起模型请求。
- 发送记录保留本轮正文与附件快照，普通追问不自动重发全部历史原件。需要重新读取时可再次附加。
- 编辑并重发、分支与失败重试保留各自上下文；重试不应覆盖正在写的新草稿。
- 来源、执行活动、审批与结果使用实际记录。模型未提供公开摘要时只显示真实状态，不编造思考内容。
- 已有任务可以继续修改日期、状态、说明与检查项；目标不明确时需要确认，旧计划不能覆盖等待期间的手动变更。

模型是否接收 PDF 原件、页面图像或提取文本由连接能力决定。取消固定本地页数截断，不等于模型请求体、上下文、网络和设备容量无限；不能据此承诺所有大小附件都可发送。公开链接读取也受访问权限、验证码和下载限制影响。

## 阅读、编辑与修改审阅

项目文件树、附件和来源可以打开文档阅读区。阅读区支持标签、宽度调整和放大；文档返回入口连接原项目、会话或任务。关闭阅读标签不会删除原件或成果。

Markdown 文档提供阅读、可视编辑和源码模式，使用实际 Milkdown/Crepe 与 CodeMirror 内核。大纲、查找、保存、草稿与版本恢复接入同一个文档身份。可视编辑只覆盖支持的语法；扩展结构应保留原文并回到源码模式。当前编辑会话支持跨可视与源码模式连续撤销；保存不清除历史，但重新读取外部版本或明确放弃修改会重置历史。重新打开可以恢复正文、草稿与选区，不持久保存整个撤销栈；较早历史也可能因内存预算释放。

支持的 AI 文档与文件修改先提供差异审阅，再按用户选择保存。待审阅建议、已保存正文与历史执行快照不能混为一份内容。页面显示“执行完成”也不意味着必然生成文档，应以可打开成果及持久保存状态为准。

## 同步与本机权限

自托管同步是可选能力。HTTPS 连接或 SSH 隧道用于推送、拉取受支持的工作区资料；当前 SSH 不提供远端目录、远端文件树、远程终端或远端 Agent。

SSH 账号用于连接主机，同步账号由服务部署者管理并确定资料归属。首次连接、恢复会话、待同步、冲突与实际完成是不同状态；连接检查成功不能代替推送/拉取完成。设置、部署和冲突说明见[同步指南](CLOUD_SYNC.md)与[服务部署](../cloud/README.md)。

访问本机项目目录和执行高影响操作遵循 App 的授权与审批设置；系统通知由 macOS 单独授权。授权目录、App 审批与操作系统权限不是同一层控制，不应相互替代。

## 开发入口

| 命令 | 用途 |
| --- | --- |
| `npm run start:native` | 编译并启动原生开发预览 |
| `npm run build:native` | 只编译原生可执行文件 |
| `npm run build:ui` | 生成 Halaska / React 组件资源 |
| `npm run build:editors` | 生成文档编辑内核资源 |
| `npm run build:document-markdown` | 生成 Markdown 阅读资源 |
| `npm run release:mac -- --output "$PWD/release/native-current"` | 从干净已提交源码生成原生 ZIP / DMG；输出目录必须不存在 |

当前预览启动器优先查找仓库内已打包的 Python，否则使用 `/usr/bin/python3`，不会自动使用激活的 `.venv` 或 `AI_WORKSTATION_PYTHON`。这是开发入口的已知限制；发行包使用自带 Python。依赖、工具链与构建步骤见[安装与构建](DISTRIBUTION.md)，不要照旧 Electron 指南替换原生包。

共享 `app/asset-manifest.json` 约束应用运行资源。组件源码修改后需重建对应 bundle；Swift 源码修改还需重编原生二进制，单独更新 JavaScript 不能完成原生变更交付。

## 验收与当前限制

功能检查、renderer 测试、发行包后端探测和原生实机验收分别证明不同范围。发布前需要核对真实 App 中的项目切换、输入与焦点、阅读/编辑/保存/返回、任务日程、退出重开，以及源码与实际安装资源的一致性。

长会话、大资料库、完整 VoiceOver、系统输入法和所有崩溃恢复路径仍需逐项验收。应用仍是开发预览，暂不提供自动更新、Windows / Linux 安装包、多人实时协作或云端 Agent。具体版本问题以 [Release](https://github.com/zihenghe04/AIBro/releases) 与[更新日志](../CHANGELOG.md)为准，不将历史单次测试推广为当前全产品保证。
